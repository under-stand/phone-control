# Phone Control 产品路线图

Phone Control 的目标不是把 Codex 聊天窗口缩小到手机上，而是成为面向 Headless Linux、GPU
服务器和多机器开发环境的移动 Agent 任务驾驶舱。

这份路线图记录产品方向，不承诺具体发布日期。优先级遵循一个原则：先让任务身份、状态和结果可信，
再扩展调度与自动化能力。

## 当前进展

第一阶段的核心切片已经落地：会话主题与当前任务分离、上下文短指令与评价反馈过滤、按需智能命名、
手动改名与恢复自动、目标/进展分离、待处理与全部筛选、本机历史全文检索、相关性排序、匹配高亮，
以及从搜索结果跳转到精确历史消息。搜索文档按会话缓存，200 个会话、48,000 条事件的预热后查询
基准约为 57 毫秒。

第二、三阶段也已经具备部分基础：回答与审批、停止/继续/新建/分叉、掉线续作队列、图片输入、目标
通知、Tailscale 与 VPS Relay、跨平台后台服务，以及可选浏览器控制。但这些能力需要先收敛到稳定的
协议、命令状态和发布链路，才能继续扩大功能面。

近期优先级调整为：

1. 统一公开 monorepo、personal 安装源、插件缓存与服务启动根，消除多份版本漂移；
2. 使用 Codex 生成的 App Server schema 做出站协议门禁，并统一直发/排队/恢复的命令状态；
3. 完成“待我处理”行动收件箱与离开期间增量摘要；
4. 建立结构化结果卡，再继续多机器统一中心。

第一阶段后续的用户标签、项目/机器/时间组合筛选、长期索引和自然语言检索保留，但不再优先于输入与
发布可靠性。详细代码审计见 [docs/repository-audit-2026-09-03.md](docs/repository-audit-2026-09-03.md)。

## 核心产品模型

- **会话（Session）**：Codex 中可持续续聊的 thread。
- **轮次（Turn）**：一次用户指令及其对应的 Agent 执行过程和结果。
- **任务（Task）**：用户能够辨认和管理的一项工作；初期通常对应会话的主要目标，后续可以跨多个轮次推进。

列表里的卡片应表达“这个任务在做什么”，而不只是展示 session ID、最后一条日志或模糊状态。

## 第一阶段：可信、可辨认、找得到

### 1. 统一任务状态模型

建立机器、会话、任务、轮次和事件之间的唯一关系，所有列表、详情、提醒与操作都从同一份派生状态生成。

目标：

- 消除重复轮次、幽灵会话、内容串线、状态漂移和陈旧审批；
- 明确区分运行中、待用户处理、完成、失败、中断与历史任务；
- 每个操作和通知都能定位到精确机器、会话、任务与轮次；
- 内部上下文、Hook 包装和系统注入内容永远不被误认为用户指令。

### 2. 有语义的任务卡片

任务卡片至少回答四个问题：

1. 这是在做什么？
2. 现在做到哪一步？
3. 是否需要我处理？
4. 最近发生了什么？

建议字段：

- 随任务切换更新的一行“当前任务”，例如“优化手机端会话详情加载速度”；
- 必要时补充稳定的“会话主题”，帮助理解这条长会话属于什么工作；
- 一至两行目标摘要，说明对象、动作与期望结果；
- 当前阶段或最近一项有意义的进展；
- 状态、项目、机器和最后活动时间；
- 待回答、待审批、失败或已完成等显著行动信号；
- 可选标签、置顶和归档；用户自定义标题已支持。

会话主题优先来自第一条可独立理解的真实用户目标并保持稳定；当前任务来自最近一条可独立理解的目标，
不能被“推一下吧”“按照你的想法做”这类上下文短指令覆盖。自动生成不确定时使用项目名称保底；用户
可以随时修改标题或恢复自动。卡片摘要只使用真实用户输入、Agent 最终回复和经过
归一化的状态，不使用系统注入内容。

### 3. 任务检索

任务数量增长后，检索是核心能力，不是附属功能。检索应覆盖：

- 任务标题与摘要；
- 项目、目录、机器和标签；
- 真实用户指令与 Agent 最终回复；
- 状态、模型、时间范围和是否需要处理。

首个版本提供本地全文搜索、组合筛选和按相关性/最近活动排序。搜索结果应直接打开命中的任务与轮次，
并高亮匹配内容。后续再增加自然语言检索，例如“上个月在 L20 机器上修过连接重试的任务”。

## 第二阶段：打开手机就知道该做什么

### 4. “待我处理”任务收件箱

首页从单纯的最近会话列表升级为行动视图：

- 需要我回复；
- 需要我审批；
- 执行失败；
- 正在运行；
- 刚刚完成；
- 暂时无需关注。

默认突出需要用户介入的少量任务，同时保留最近任务和搜索入口。

### 5. 结构化结果审阅

将最终回复进一步整理为适合手机判断的交付卡片：修改文件、Git diff、测试结果、命令输出、错误警告、
图片附件、可下载产物和最终结论。用户无需翻阅完整过程就能判断任务是否完成、哪里有问题以及下一步做什么。

### 6. 离开期间的进度摘要

用户回到页面时展示自上次查看后的变化：已完成事项、当前步骤、阻塞原因、是否需要介入和新增结果。
摘要应基于增量事件生成，避免重复通知或用大量原始日志淹没有效信息。

## 第三阶段：多机器与任务编排

### 7. 多机器统一控制中心

统一展示家中电脑、工作站、GPU 服务器和 VPS 上的任务、项目与在线状态。用户只需选择机器和项目，
不必理解每台机器背后的 URL、端口或接入方式。

### 8. Agent 任务编排

在精确状态基础上支持暂停、取消、继续、修改目标、指令排队、任务优先级、完成后执行下一条、从现有
会话派生新任务，以及在合适的情况下将任务交给另一台机器。

### 9. 完整移动输入

继续完善图片、语音和文件输入：拍照或截图发送、系统分享至 Phone Control、语音转指令、上传日志和
文档，以及将一组文字和附件可靠地绑定到目标任务。

### 10. 可执行通知

通知可直接查看结果、回复、重试、继续、取消或稍后处理，并严格绑定产生通知的任务和轮次。页面内提醒、
系统通知和完成声音共享同一去重规则。

## 第四阶段：项目工作区与自动化

### 11. 项目工作区

围绕项目聚合相关会话、分支、工作区状态、测试、产物、常用指令和待办事项，让任务不再是孤立聊天记录。

### 12. 自动化和定时任务

支持定时测试、训练完成提醒、GPU 作业异常分析、CI 失败后创建修复任务、日志监控和每日任务简报，
逐步从远程控制台发展为可持续运行的 Agent 自动化平台。

## 推荐实施顺序

1. 统一任务状态模型；
2. 有语义的任务卡片；
3. 本地任务检索与筛选；
4. “待我处理”收件箱；
5. 结构化结果审阅与离开期间摘要；
6. 多机器管理与任务编排；
7. 项目工作区和自动化。

近期不优先投入完整手机终端、复杂代码编辑器或单纯的视觉主题扩展。Phone Control 应首先把“找到任务、
理解状态、做出决定、继续推进”这条移动路径做到足够快和可靠。
